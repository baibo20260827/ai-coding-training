# 三类自学路径

版本 v1.1 · 2026-10-04。你可以按自己的起点，逐步完成阅读、操作、练习和自检。每一步都有可保存的产物，下一次从尚未完成的检查继续，不要求一次读完整套材料。

案例和管理情境均为虚构学习材料。已有工程检查见[验证记录](../evidence/VALIDATION.md)，它不能代替你本次的实际操作，也不能证明真实客户已经接受或个人能力已经达到要求。

## 从最接近你的困难开始

先读[三个小失败](00-opening.md)，写下一句自己最想解决的问题，再选择一条主路径。需要补另一类能力时，可以返回此处切换。

| 路径 | 适合的起点 | 读完并实践后应留下什么 |
|---|---|---|
| 部门主管 | 要判断进度、风险、人员与工具投入；不要求先会写代码 | 一份基于证据的状态判断、一份变更方案比较、一份接管与培养安排 |
| 资深开发者 | 能读代码，但希望降低 AI 修改的审查和返工成本 | 一张任务卡、一组独立验收例子、一次小变更的差异与验证记录 |
| 无编码经验者 | 有业务想法，不清楚如何设计、实现和检查 | 一页场景卡、一份亲手操作的验收记录、一条可复现的求助信息 |

## 部门主管：从“看起来快”走到有依据的承诺

1. 读[主管指南](../docs/guides/manager.md)和[案例需求](../docs/case/requirements.md)，完成 [L1](exercises.md)：区分本期范围、验收条件与待确认事项。
2. 按[端到端操作](../demo/WALKTHROUGH.md)查看成果与证据；能运行时亲手验证一个行为，暂不能运行时阅读现有证据并注明“本次未执行”。
3. 对照[一页周报](../docs/case/weekly-report-example.md)与[变更情境](../docs/case/change-example.md)，完成 L5，分别记录已批准承诺、当前预测和待决策事项。
4. 完成 L6，检查团队能否凭文件接管；用[能力与试点模板](../templates/capability-pilot.md)规划下一项真实任务的责任和验证方式。

**自检：** 你能否说明每个进度判断的证据，解释新增工作为何影响或不影响日期，给出至少两种可行方案，并找出有权确认的人？完成后对照[自检参考解析](answer-key.md)的 L1/L5/L6。

**卡住时：** 日期和范围问题查[变更模板](../templates/change-control.md)及 [FAQ](../faq/README.md)；组织权限不明时向项目授权人确认。阅读[主管 PPT](slides/manager.pptx)可回顾核心关系，不需要先完成编码练习。

## 资深开发者：从怀疑到可执行的约束与检查

1. 读[工程师指南](../docs/guides/engineer.md)、[需求](../docs/case/requirements.md)和 [4A](../docs/case/architecture.md)，确认业务边界和实际保护机制。
2. 按[案例运行说明](../demo/README.md)启动，完成 L2，再做 L3。先自己写边界例子，再运行故障脚本，比较测试结果与需求判断。
3. 在独立练习副本中完成 L4，使用[任务卡 2–5](ai-task-cards.md)约束修改范围、审查差异并记录真实检查结果。
4. 运行备份恢复演练，完成 L6。留下下一位维护者可以直接使用的运行、验证和恢复信息。

**自检：** 你能否发现测试预期被改错的情况，说明数据库约束怎样处理并发，以及为何接受或退回这次变更？用[参考解析](answer-key.md)核对边界和测试适配，保留有依据的不同实现。

**卡住时：** 先缩小为一个失败例子，再查 [FAQ](../faq/README.md)与[排查任务卡](ai-task-cards.md)。涉及未知数据、权限或跨团队接口时，带证据向相应负责人求助。[工程师 PPT](slides/engineer.pptx)适合回顾整条工作链。

## 无编码经验者：从想法到亲手可验收的行为

1. 读[新手指南](../docs/guides/beginner.md)和[自学实践指南](facilitator-guide.md)，用“输入、规则、数据、输出”描述一个预约场景，完成 L1。
2. 按[案例 README](../demo/README.md)启动；跟随[端到端步骤](../demo/WALKTHROUGH.md)完成 L2，逐条填写预期与实际结果。
3. 使用[任务卡 1](ai-task-cards.md)检查需求是否说清楚，使用任务卡 5整理一个问题。把错误原文、复现步骤和已尝试检查写下来。
4. 选择 L4 的需求与验收部分作为进阶：写午休边界例子和影响问题。准备修改代码时先保留练习副本；遇到无法判断的设计或代码，让具备相应能力的人复核，并注明获得了哪些协助。

**自检：** 你能否说清页面、服务端和数据库各负责什么，亲手验证刷新保留、相邻允许、重叠拒绝和取消释放，并描述一个尚未验证的范围？对照[参考解析](answer-key.md)的 L1/L2；只完成需求部分时，不把实现记为完成。

**卡住时：** 页面打不开查[运行说明](../demo/README.md)；不知道如何描述问题查 [FAQ](../faq/README.md)与[求助流程](../docs/guides/mentoring.md)。[新手 PPT](slides/beginner.pptx)可帮助回顾基本概念。

## 准备与记录

- 运行案例需要组织准入的 Python 3、浏览器和完整项目目录，无需安装额外 Python 包。Windows 命令见案例 README。
- 使用 AI 协作时选择部门准入工具，先让工具读取项目约定。模型服务不可用时，现有应用、故障脚本、模板与练习仍可使用。
- 为每项练习保存需求版本、产物、实际检查、未验证项、协助情况与下一步。记录格式在[练习册](exercises.md)末尾。
- 完成练习后再对照[解析](answer-key.md)，修正不成立的判断，并用新例子重试。自检结果用于找到下一项学习任务，真实项目的技术把关与客户验收仍由相应责任人承担。

全部材料与模板见[索引](../docs/guides/README.md)。重复遇到的困惑可以按[改进日志](../docs/IMPROVEMENTS.md)格式记录，帮助后续读者更快完成同样的任务。
