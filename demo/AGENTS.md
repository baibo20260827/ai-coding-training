# 教学案例工作约定

先读本目录 [README](README.md)、[需求与追踪](REQUIREMENTS.md)，并遵循根目录规则。

- 基线 R01–R08：单会议室、09:00–18:00、30 分钟粒度、单条预约限一天、本地单时区。使用虚构数据。无登录、审批、多租户与生产部署承诺。
- Python 标准库 HTTP + SQLite + 原生 HTML/CSS/JS；本版无第三方依赖、CDN 或后台外联。代码兼容 Python 3.9+；实际选用组织准入且仍受维护的版本。
- 默认且仅绑定 `127.0.0.1`。不得为方便演示改成公网或 `0.0.0.0`。本机访问保护不等于身份认证。
- 主应用以事务和占用时段唯一约束保证冲突规则；不要用无事务的“先查再插”替代。取消须同时释放占用时段。
- 测试预期来源于需求基线。改动测试预期须说明业务依据；区分单元/接口检查、浏览器操作、客户接受与学习效果。
- 故障代码只放 `labs/` 并明确标注，主应用保持正确基线。练习答案不得未经需求决策合并到主基线。
- 仅对临时目录或本轮明确创建的数据做演练。备份与恢复必须输出到新路径，已有目标拒绝覆盖。不要删除未知数据库或用 Git 命令清理用户变更。
- 修改后执行适用检查：`python3 -m unittest discover -s demo/tests -v`；故障与恢复分别为 `python3 demo/labs/failure_lab.py`、`python3 demo/backup.py exercise`。从项目根目录执行。
- 证据维护在 [验证记录](../evidence/demo/VALIDATION.md)，如实记录环境限制。运行时用户数据 `data/` 不作为教材提交。
