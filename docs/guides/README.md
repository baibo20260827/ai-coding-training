# 实践材料入口

版本：1.1；日期：2026-10-04。供主管、工程师和无编码经验者独立学习、实践与复查，按个人起点和成果安排进度。

本目录中的流程为本项目建议；会议室案例、角色、工期和周报均为虚构教学材料。真实客户确认、人员独立任务评审及收益测量尚未执行。实际软件检查以项目验证记录为准。

## 按角色开始

先读共同的[三个小失败开篇](../../training/00-opening.md)，再选择路线。先记下你目前不能回答的一个问题，完成对应任务后再回答一次。三类人共享同一需求、代码和证据，不要求分别维护三套业务规则。

| 对象 | 主要材料 | 本次需要产出的结果 |
|---|---|---|
| 主管 | [主管指南](manager.md)、[周报案例](../case/weekly-report-example.md)、[变更案例](../case/change-example.md) | 一项有依据的范围/日期/资源决定 |
| 工程师 | [工程师指南](engineer.md)、[需求](../case/requirements.md)、[4A 架构](../case/architecture.md) | 可审查任务、独立验证与接受/退回结论 |
| 新手 | [新手指南](beginner.md)、[需求](../case/requirements.md) | 可验证的小需求、操作记录和清楚的求助信息 |
| 遇到困难的读者与协作评审者 | [问题排查与协作求助](mentoring.md)、[FAQ](../../faq/README.md) | 可复现问题、已尝试步骤及下一项验证 |

## 自学时怎样使用材料

1. 读角色指南中的例子，先写自己的判断；遇到术语查指南与 FAQ。
2. 按步骤操作或完成决策推演，记录实际结果，不直接复制参考答案。
3. 对照完成标准和[参考答案](../../training/answer-key.md)，写清差异及原因，修正后再试。
4. 换一个输入或小任务独立完成，把证据记入[自评模板](../../templates/capability-pilot.md)。仍受阻时按[排查与求助](mentoring.md)补齐信息。

完成阅读不等于完成实践。上述步骤可独立完成；真实项目的客户验收、技术评审与承诺变更由有权限的人承担。

## 可复制模板

使用方法：保留“填写说明”，删除“教学示例”后填写真实信息；未确认项写“待确认＋责任人”，不要让示例姓名、日期或批准状态进入真实项目。

| 模板 | 何时使用 |
|---|---|
| [客户场景与验收基线](../../templates/scenario-baseline.md) | 开始新项目、选试点、确认需求 |
| [任务委派与审查](../../templates/task-review.md) | 每个有边界的实现、修复或验证任务 |
| [周报与里程碑](../../templates/weekly-milestone.md) | 定期报告与阶段评审 |
| [变更影响、选项与确认](../../templates/change-control.md) | 已确认范围或承诺需要调整 |
| [部署对齐表](../../templates/deployment-alignment.md) | 与客户、IT、运维确认交付环境 |
| [简明 DfX 矩阵](../../templates/dfx-matrix.md) | 规划并确认运行质量要求 |
| [能力自评与真实任务复盘](../../templates/capability-pilot.md) | 开始学习、独立新任务完成后及真实项目推广决策 |

## 一个任务的完整材料链

先从[案例需求](../case/requirements.md)找到需求与验收编号，再用[架构视图](../case/architecture.md)定位业务、应用、数据和技术影响，用任务模板记录变更和验证。对照[阶段报告示例](../case/weekly-report-example.md)汇报已实现、已验证和已接受状态。新增审批的演练使用[变更示例](../case/change-example.md)，不在当前本地应用中实施审批。

交付前检查：链接可打开；案例标签清楚；文档与当前代码口径一致；命令确实执行后才记“通过”；客户或实际使用者尚未参与的环节保留“未执行”。
